# 文档规范

## 命名方式

- 文件名使用小写短横线：`getting-started.md`
- 页面标题使用清晰主题，不做营销口号
- 文档主名称统一为 `CHun`

## API 页统一结构

每个 API 页面按以下顺序组织：

1. 类/模块职责
2. 初始化参数或输入输出
3. 关键属性/方法
4. 使用示例
5. 注意事项与边界

## 示例代码风格

- 优先使用 `from chun import Tool, Blind, Reg`
- 示例要可运行或接近可运行，避免伪代码堆砌
- 对 Future work 明确标注，不伪装为已实现

## README 与 docs 的边界

- README：一句话介绍、安装、最小示例、文档入口
- `docs/`：完整设计、API、迁移、实战流程

## Wiki 的使用边界

- 默认不依赖 Wiki 承载核心文档
- 只有临时讨论稿、草案或社区协作记录才考虑放 Wiki
- 一旦内容稳定，应回迁到仓库 `docs/`
